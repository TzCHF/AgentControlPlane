# 商业化路线图

> [English](COMMERCIALIZATION.md)

## 建议的产品拆分

采用开放的本地智能体加托管中继：

```text
MCP-capable web AI
        |
        v
hosted relay (identity, device routing, policy, billing)
        |
        v  outbound authenticated connection
local AgentControlPlane (workspace, executors, state, audit)
```

本地组件默认保留源代码、文件系统访问、执行器凭据、命令输出和详细事件。托管中继只承载紧凑的加密任务信封与状态。

这为终端用户省去了公网 IP、端口转发以及按提供商配置隧道的步骤。用户安装桌面/本地服务，登录，配对一台设备，即可为受支持的网页 AI 产品获得一个稳定的 MCP 端点。

## 托管中继的职责

- 账户与组织身份；
- 设备注册、短期凭据、轮换与吊销；
- 来自本地智能体的出站 WebSocket 或 HTTP/2 连接；
- 租户隔离的任务路由与重放保护；
- 面向 MCP 的 OAuth 与特定提供商的连接器元数据；
- 套餐权益、速率限制、健康状态与更新渠道；
- 保护隐私的运维遥测与审计导出。

中继不得直接暴露当前的 loopback 服务器。任务进入队列之前，本地执行必须要求设备绑定的签名请求、工作区策略校验以及新生成的 nonce/到期时间。

## 付费托管 Beta 前的要求

1. 针对中继、桌面智能体、配对、更新与执行器机密的威胁模型。
2. MCP 兼容的 OAuth，以及设备授权与吊销。
3. 每租户加密持久化与严格的授权测试。
4. 签名的桌面安装程序、可复现构建与经过验证的自动更新。
5. 端到端请求认证、重放保护与有界队列。
6. 针对任务元数据、保留、导出与删除的隐私控制。
7. 针对每个网页控制器与工程执行器的兼容性矩阵。
8. 使用量仪表盘、计费权益、支持、条款与隐私政策。
9. 依赖许可证审查与独立的应用程序安全评估。

## 许可模式

当前源码按 GNU Affero General Public License 3.0（`LICENSE`）提供。已发布版本 v0.1.0 至 v0.4.2 继续按 Apache License 2.0 提供，原文存档于 `docs/LEGACY-LICENSE-APACHE-2.0.md`。

将 AgentControlPlane 作为商业服务运营，需要与版权方签署书面协议；请联系仓库所有者获取商业条款。"AgentControlPlane"名称与标志为商标，各许可证均不授予商标使用权。AI 中转站与 AgentControlPlane 的配对方式见 `docs/AI-RELAY-INTEGRATION.zh-CN.md`。

托管中继应位于独立的仓库和独立的法律分发边界内。中继运营、托管身份、计费、企业策略、品牌、支持与托管基础设施，不会仅仅因为与该仓库的公共协议互操作，就自动获得该仓库的许可。

商业差异化来自受管网络、可信分发、支持、兼容性认证、企业管控和运营可靠性。

## 宣传主张与经济效益

不要将产品宣传为绕过配额。其可衡量的价值是更短的交接时间、更少的重复提示、更少的执行器误解、可持久保存的证据，以及将每个任务路由到最合适的已授权执行器的能力。节省 token 的主张只能基于重复运行且修订版本固定的直接与受控对照基准测试。
