# 跨设备路线图

本文记录面向社区公开、欢迎讨论的产品方向。它不是发布日期承诺、技术实现规范，
也不是托管服务公告。

## 目标

让用户能在电脑或手机的已支持网页 AI 中讨论工程任务，确认一份精简简报后发送到
自己的电脑，并在同一网页看到本地执行器返回的验证结果。

代码的读取、修改和测试始终发生在用户自己的电脑上。网页只承担控制和确认，不是
远程代码执行环境。

## 公开规划方向

### 桌面网页桥接

现有浏览器 Companion 继续作为桌面端主集成。后续可能提供油猴脚本形式的网页桥接，
方便希望轻量安装的用户，也便于更快试验新的网页 AI 适配。

### 手机网页桥接

手机端的目标是在支持的手机网页中准备和确认任务，并查看任务状态和验证证据。
手机端不直接执行本地工程命令。

### 设备连接方式

用户应能按自己的情况选择连接方式：

- 同一可信网络下的局域网连接；
- 降低配置门槛的托管中继；
- 由用户自行控制部署的兼容中继。

每种方式的可用性、支持平台和运行限制，都会在完成测试后再公布。

### 支持的网页 AI

站点支持通过可独立测试的小型适配器逐步增加。第一批候选是 ChatGPT 与 DeepSeek
网页。其他站点将根据能否安全提供用户确认过的精简简报、并展示紧凑结果来评估。

### 执行器选择

控制面保持执行器中立。用户可选择已就绪的本地执行器，例如 OpenCode、Codex、
Claude Code 或已配置的兼容模型端点。网页 AI 不会获得超出本地 ACP 策略的执行权限。

## 有意不在此公开的内容

本文不公开认证实现细节、设备配对密钥、中继拓扑、滥用防护、基础设施供应商、
运维流程、定价或尚未发布的安全工作。
