# 安全审查

> [English](SECURITY-REVIEW.md)

审查日期：2026-08-13

范围：当前的第一方源代码、配置、测试、脚本和项目文档。依赖项在集成边界处进行了检查，但本次审查不是在线漏洞公告扫描。

## 受支持的安全边界

本版本仅批准用于本地单用户部署：

- HTTP 服务器仅绑定回环地址；
- 远程 ChatGPT 访问使用 Secure MCP Tunnel 或单独的 TLS 网关；
- 每个工程工作区都必须位于已列入允许列表的根目录之下；
- 控制平面状态和 Codex 可执行文件必须保留在工作区根目录之外；
- Codex 以 workspace-write 权限运行，默认禁用网络，使用经过清理的环境，并拒绝提权请求；
- 一个项目工作区最多有一个活动的 Codex turn；
- 取消、运行时、队列、令牌预算、任务保留、审计日志大小、MCP 会话、请求体大小和事件保留限制均已强制执行。

## 已修复的问题

本次审查发现的问题已由实现修复：

- 取消后仍启动的排队任务；
- 迟到的完成覆盖已取消状态；
- 超时任务在无中断请求的情况下继续运行；
- 并发任务共享同一项目线程并接收彼此的事件；
- 无限制的队列、令牌预算、存储任务、审计日志和 MCP 会话；
- 状态文件和审计文件可从允许的工程工作区访问；
- 工作区路径在准入与执行之间被替换；
- 通过 PATH 回退查找 Codex 可执行文件；
- 非回环连接上的明文 bearer-token 部署；
- 公开健康检查响应中包含详细的本地运行时信息；
- 不准确的破坏性/开放世界 MCP 工具注解；
- 缺少取消和运行时中断的审计记录。

## 已接受的限制

以下各项在受支持的单用户边界内不视为漏洞，但会阻碍不受信任或多租户场景的商业化部署：

- `workspace-write` 限制写入，但不是通用的机密读取沙箱。有权派发 Codex 的用户必须已被信任可访问本地账户的可读数据。
- 本地 bearer token 是单一的共享操作员机密，不承载按用户的身份或授权。公开部署需要兼容 MCP 的 OAuth 2.1 和按用户策略。
- 状态持久化是受限的本地 JSON 存储。商业规模应使用事务性存储、租户隔离、按主体的配额、分布式限流、加密的机密管理和带签名的审计导出。
- 本次审查在内部进行。公开或有偿发布需要独立的外部评估和依赖项公告扫描。

## 验证

本版本通过以下命令验证：

```text
npm.cmd test
npm.cmd run check
npm.cmd run doctor
npm.cmd run smoke
```

冒烟测试会启动真实的 Codex app-server，初始化所有 MCP 工具，执行一个只读项目任务，继续同一项目，并验证 Codex 线程得到复用。
